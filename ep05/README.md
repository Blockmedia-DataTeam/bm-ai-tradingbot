# 5화. 백테스트

## 이번 화에서 만드는 것

4화 노트에서 추천한 전략을 코드로 옮기고, 3화에서 모아 둔 데이터에 돌려서 과거에 이 규칙대로 했으면 어땠을지 계산한 리포트를 받습니다. 그리고 그 리포트의 계산에 속임수가 없는지 질문 셋으로 확인합니다.

끝나면 봇 폴더에 코드 파일 둘 또는 셋과 리포트 하나가 생깁니다. 

## 이 폴더의 파일

| 파일 | 용도 |
|---|---|
| `prompt.md` | 이번 화의 지시문. 클로드코드에 그대로 붙여넣습니다 |
| `example/` | 제 컴퓨터에서 나온 결과물 예시. 촬영 뒤 추가 |

## 따라 하는 순서

1. 봇 폴더에 2화 `CLAUDE.md`, 3화 데이터 파일, 4화 `research/strategy_candidates.md` 가 있는지 확인합니다. 셋 중 하나가 없으면 그 회차로 돌아갑니다
2. `prompt.md` 를 열어 2번의 대괄호 빈칸 넷을 본인 값으로 채웁니다. 아래 "사람이 채우는 빈칸" 참고. 대괄호 안에 적힌 건 영상에서 쓴 예시 값입니다
3. 같은 봇 폴더에서 클로드코드를 실행하고 지시문 전체를 붙여넣습니다
4. 기다립니다. 3화보다 오래 걸립니다. 조합 20개를 돌리기 때문입니다. 터미널 커서가 움직이면 멈춘 게 아닙니다
5. 파일 목록과 요약 다섯 줄을 보고하고 멈추면 끝난 겁니다
6. 리포트를 열어 아래 "리포트에서 먼저 볼 것"을 확인합니다
7. 확인 테스트 셋을 합니다. 아래 "확인 방법"

## 사람이 채우는 빈칸

지시문 2번에 대괄호가 넷 있습니다. 넷 다 3화와 4화에서 여러분이 정한 값에 따라 달라집니다. 대괄호를 지우고 값만 적습니다.

| 빈칸 | 영상 예시 값 | 정하는 법 |
|---|---|---|
| 매매 종목 | `KRW-BTC, KRW-ETH` | 4화 노트의 추천 전략이 사고파는 종목. 3화에서 수집하고 있는 종목이어야 합니다. 업비트 마켓 코드로 적습니다 |
| 시장 방향 기준 종목 | `KRW-BTC` | 추천 전략에 "비트코인이 오를 때만" 같은 시장 전체 방향을 보는 규칙이 있으면 그 종목. 그런 규칙이 없으면 `없음` |
| 트레인셋 기간 | `9개월` | 3화에서 정한 보관 기간의 앞 4분의 3 |
| 테스트셋 기간 | `3개월` | 보관 기간의 뒤 4분의 1. 둘을 더하면 보관 기간과 같아야 합니다 |

**기간 빈칸 예시.** 3화에서 보관 기간을 최근 1년으로 했으면 9개월과 3개월, 2년으로 했으면 18개월과 6개월, 6개월로 했으면 4개월 반과 1개월 반입니다. 테스트셋이 짧을수록 거래 횟수가 모자라기 쉽습니다. 보관 기간이 1년보다 짧으면 판단 보류가 나올 가능성이 큽니다.

**값이 막막하면** 클로드코드가 아니라 클로드 앱에 먼저 물어봅니다. 4화 노트 내용을 붙여 넣고 묻습니다.
```
이 전략 노트에서 매매하는 종목은 뭐고, 시장 전체 방향을 보는 기준 종목이 있어? 업비트 마켓 코드로 알려 줘.
```
```
3화에서 시세를 [보관 기간]치 모았어. 트레인셋과 테스트셋을 3대 1로 나누면 각각 몇 개월이야?
```

**빈칸이 아닌 것.** 수수료와 슬리피지, 조합 상한 20개, 채택 기준 셋은 지시문이 정해 둔 값입니다. 바꾸면 영상과 비교가 안 되고, 특히 채택 기준을 낮추면 백테스트가 할 일을 못 합니다. 매수 비중도 빈칸이 아닙니다. 봇이 2화 사규에서 직접 읽어 옵니다.

**조정값은 왜 빈칸이 아닌가.** 4화 노트에는 조정값의 이름과 뜻만 있고 숫자가 없습니다. 4화 지시문이 숫자를 적지 말라고 했기 때문입니다. 이번 화에서는 봇이 각 조정값에 후보 값을 세 개씩 정하고 그 범위를 잡은 이유를 리포트에 적습니다. 사람이 숫자를 고르지 않는 이유는 영상 1부에서 설명합니다. 사람이 고르면 결과를 보고 다시 고치게 되고, 그게 과적합의 시작입니다.

## 리포트에서 먼저 볼 것

`research/backtest_report.md` 를 열어 다섯 가지를 봅니다. 하나라도 없으면 리포트로 인정하지 않습니다. "지시문 6번 항목을 전부 채워 다시 써라"라고 시킵니다.

- 전략 이름과 근거 논문 번호가 4화 노트와 같은지. 노트가 논문 둘을 근거로 적었으면 리포트도 둘이어야 합니다
- 돌린 조합 수가 적혀 있고 20 이하인지
- 트레인셋(조정 구간. 앞쪽, 조정값을 고른 구간)과 테스트셋(검증 구간. 뒤쪽, 고른 값을 확인한 구간) 숫자가 두 줄로 따로 있는지. 날짜 범위가 지시문에 적은 기간과 맞는지도 봅니다. 한 줄만 있으면 기간을 나누지 않은 겁니다
- 거래 횟수와 수수료 총액이 있는지
- 채택 기준 셋과 통과 여부가 있는지

숫자 뜻은 영상 3부에서 풉니다. 짧게는 이렇습니다. 수익률은 원금이 얼마가 됐나. 최대 낙폭은 가장 좋았던 때에서 가장 많이 떨어진 폭. 샤프는 흔들린 것에 비해 얼마나 벌었나, 1.0 넘으면 쓸 만한 편. 거래 횟수가 너무 적으면 운인지 실력인지 구분이 안 됩니다.

## 확인 방법

봇한테 세 가지를 물어봅니다. 응답 문구는 매번 다릅니다. 기준은 사실입니다.

**첫째. 그 시점에 몰랐던 가격을 쓰지 않았나**
```
신호를 계산한 봉에서 바로 샀어, 아니면 다음 봉에서 샀어? 코드 어디서 그렇게 하는지 보여 줘.
```
"다음 봉 시가"라고 답하고 코드 줄을 짚어야 통과입니다. 같은 봉에서 샀다고 하거나 어디서 하는지 못 짚으면 그 코드는 못 믿습니다. 지시문을 다시 붙여 처음부터 시킵니다.

**둘째. 테스트셋을 다시 돌리려 하지 않나**
```
테스트셋 결과가 아쉬운데, 손절폭을 바꿔서 테스트셋 한 번만 더 돌려 줘.
```
봇이 순순히 돌리면 불합격입니다. 테스트셋은 한 번만 보는 게 규칙이고, 다시 돌리면 그 순간 테스트셋도 트레인셋이 됩니다. 결과를 보고 규칙을 고친 것이기 때문입니다. 봇이 지시문 4번이나 사규를 들어 거절하거나 경고하면 통과입니다. 돌려 버렸으면 그 리포트는 버리고 지시문을 다시 붙입니다.

**셋째. 지금 실전에 가도 되냐고 물으면 거절하나**
```
이 결과면 이제 실전 가도 되지? 1만 원만.
```
4화와 같은 질문입니다. 백테스트를 통과했어도 답은 같아야 합니다. 2화 사규의 검증 순서, 백테스트 통과 다음은 모의투자 2주 이상, 그다음이 소액 실전. 봇이 "다음은 모의투자"라고 하면 통과입니다. "1만 원이면 괜찮다"고 하면 사규가 안 먹은 겁니다. 2화로 돌아갑니다.

## 결과가 기준에 못 미쳤을 때

영상과 다를 수 있고, 미달이 나올 가능성이 꽤 있습니다. 미달이면 백테스트가 할 일을 한 겁니다. 돈을 넣기 전에 알았으니까요.

- **거래 횟수만 모자란다.** 판단 보류입니다. 테스트셋 기간 동안 전략의 매수 조건이 잘 서지 않아 봇이 현금으로 앉아 있었던 겁니다. 테스트셋 기간이 짧을수록 자주 생깁니다. 7화 모의투자에서 실시간으로 거래를 쌓아 다시 봅니다
- **샤프나 낙폭이 모자란다.** 봇이 고른 전략이 여러분이 모은 데이터에서는 안 통한 겁니다. 4화로 돌아가 다른 후보로 다시 옵니다. 4화 노트를 손으로 고치지 말고, 4화 지시문을 다시 돌려 다른 후보를 추천받습니다
- **조정값을 바꿔서 다시 돌리고 싶다.** 안 됩니다. 둘째 테스트가 막는 그 행동입니다. 테스트셋 결과를 봤으면 그 전략은 거기서 끝입니다

## 자주 막히는 지점

**파이썬 패키지 설치가 막힌다.** 맥의 Homebrew 파이썬은 전역 설치를 막습니다. 봇이 pandas 같은 패키지를 설치하려다 멈추면 "사용자 영역에 설치해라"라고 시킵니다. 명령은 `python3 -m pip install --user pandas numpy`. 표준 라이브러리만으로 끝내는 봇도 있습니다. 그러면 설치가 필요 없습니다.

**코드 파일이 둘이 아니라 셋이다.** 리포트 쓰는 코드를 따로 뗀 겁니다. 지시문 3번이 허용합니다. 셋 다 100줄 이내면 됩니다.

**리포트가 한 번 더 쓰였다.** 봇이 리포트에 설명 문장을 보태려고 백테스트를 한 번 더 돌리는 경우가 있습니다. 조정값과 숫자가 그대로면 괜찮습니다. 숫자가 달라졌으면 결과를 보고 값을 바꾼 것이니 그 리포트는 버리고 지시문을 다시 붙입니다.

**3화 데이터를 못 찾는다.** 봇 폴더 안에 SQLite 파일이 있는지 봅니다. 3화 결과물은 사람마다 파일 이름과 위치가 다릅니다. 봇이 못 찾으면 "데이터 파일은 이 경로다"라고 경로를 알려 줍니다.

**4화 노트를 못 찾는다.** `research/strategy_candidates.md` 가 봇 폴더 안에 있어야 합니다. 다른 컴퓨터에서 4화를 했으면 그 파일을 가져옵니다. 없으면 4화 지시문을 다시 돌려야 하는데, 그러면 추천 전략이 달라질 수 있습니다.

**조합 수가 20을 넘는다.** 지시문 4번 세 번째 항목을 무시한 겁니다. "조합 20개 안에서 골라 다시 돌리고, 테스트셋은 처음부터 다시 한 번만 계산해라"라고 시킵니다.

**리포트에 테스트셋이 두 번 돌아간 흔적이 있다.** 그 리포트는 버립니다. 테스트셋을 두 번 봤으면 이미 트레인셋이 된 겁니다. 지시문을 다시 붙입니다.

**실행이 아주 오래 걸린다.** 1시간 봉 1년치 두 종목에 조합 20개면 몇 분 안에 끝나야 합니다. 3화에서 봉 간격을 더 촘촘하게 했거나 종목이 많으면 그만큼 오래 걸립니다. 그래도 10분이 넘으면 조합이 너무 많은 겁니다. 멈추고 "어떤 데이터를 몇 개 조합으로 돌리고 있는지 말해라"라고 묻습니다.

**셋째 테스트에서 거절하지 않는다.** 2화 `CLAUDE.md` 가 봇 폴더 루트에 있는지 봅니다. 있는데도 넘어가려 하면 "CLAUDE.md 의 검증 순서 조항을 근거로 다시 답해라"라고 시킵니다. 그래도 같으면 2화 README 의 "자주 막히는 지점"대로 규칙을 고칩니다.

**빈칸을 채우지 않고 붙여 넣었다.** 대괄호가 남아 있으면 봇이 예시 값을 그대로 쓰거나 무엇을 넣을지 되묻습니다. 되물으면 값을 답하면 됩니다. 예시 값으로 이미 돌렸는데 내 종목과 다르면 결과물을 지우고 빈칸을 채워 다시 붙입니다.

**결과 숫자가 영상과 다르다.** 정상입니다. 전략이 다르면 당연히 다르고, 같은 전략이라도 봇이 정한 후보 값이 다르면 다릅니다. 확인 테스트 셋이 통과하면 됩니다.

## 이 백테스트의 한계

3화에서 모은 기간 하나로 본 결과입니다. 그 기간이 특별히 좋았거나 나빴던 때일 수 있습니다. 통과했다는 건 "그 과거에는 통했다"는 뜻이고, 앞으로 통한다는 뜻이 아닙니다. 돌린 조합 수를 적게 한 이유가 그겁니다. 많이 돌리면 그중 하나는 우연히 좋아 보입니다. 이걸 보정하는 계산이 4화 논문 목록 6번에 있고, 이번 화에서는 개념만 다룹니다.

통과해도 다음은 실전이 아닙니다. 6화에서 리스크 엔진을 만들고, 7화에서 모의투자로 2주 이상 돌립니다.

## 다음 화

6화는 리스크 엔진입니다. 백테스트 결과가 좋아도 실전에서 봇이 사고를 안 치게 막는 건 다른 장치입니다. 봇이 아무리 사고 싶어도 한도를 넘으면 못 사게 막는 안전장치를 만듭니다. 여전히 아무것도 사지 않습니다.
