# 3화 지시문: 시세 수집기와 잔고 조회기 만들기
2화와 같은 봇 폴더에서 클로드코드를 실행한 뒤, 아래를 그대로 붙여넣는다. 같은 폴더여야 2화에서 만든 CLAUDE.md 가 적용된다. 대괄호 세 개만 본인 값으로 채운다. 값이 막막하면 README.md 의 "사람이 채우는 빈칸"을 먼저 본다.

API 키는 지시문을 넣기 전에 발급받아 `.env` 파일에 넣어 둔다. 절차는 api-key-guide.md.

```
업비트 KRW 시장의 시세를 모으는 수집기와, 내 계좌 잔고를 읽는 조회기를 만들어라.
시작하기 전에 이 폴더의 CLAUDE.md 를 읽고 따른다.

1. 내가 정한 값 (이 값은 내가 정한다. 네가 바꾸지 않는다)
   - 종목: [KRW-BTC, KRW-ETH]
   - 봉 간격: [1시간]
   - 보관 기간: [최근 1년]

2. 만들 것
   - 수집기. 업비트 공개 시세 API 로 위 종목의 캔들을 받아 이 폴더 안 SQLite 파일 하나에
     저장한다. API 키를 쓰지 않는다. 다시 실행하면 이미 있는 봉은 건너뛰고 빠진 봉과
     새 봉만 받는다.
   - 검사기. 저장된 캔들에서 빠진 봉, 겹친 봉, 이상한 값(0 이하 가격, 고가가 저가보다
     낮은 봉 등)을 찾아 건수와 시각을 터미널에 요약해 출력한다.
   - 잔고 조회기. 이 폴더의 .env 파일에서 UPBIT_ACCESS_KEY 와 UPBIT_SECRET_KEY 를 읽어
     KRW 잔고만 출력한다.

3. 데이터 규칙
   - 봉 하나는 (종목, 봉 간격, 봉 시작 시각) 조합으로 유일하다. 같은 봉이 두 번 저장되지
     않게 한다.
   - 빠진 봉은 업비트에 다시 요청해 본다. 업비트에도 없으면 그 시간에 거래가 없던 봉이다.
     결측으로 세지 말고 "업비트에도 없음"으로 따로 보고한다.

4. 지킬 것
   - 업비트 요청 사이에 간격을 두고, 요청 수 제한에 걸리면 기다렸다가 다시 시도한다.
     한 번에 받을 수 있는 봉 수 한도는 업비트 문서에서 확인하고 그 안에서 나눠 받는다.
   - .env 파일은 읽어서 쓰기만 한다. 내용을 화면에 출력하거나 채팅에 적지 않는다.
     키 문자열을 코드 파일에 쓰지 않는다.
   - 주문과 관련된 API 는 호출하지 않는다. CLAUDE.md 가 허용하기 전까지 키는 잔고 조회에만
     쓴다.
   - 필요한 프로그램이 없으면 설치 방법을 먼저 알려주고 내 확인을 기다린다.
   - 파일은 수집기, 검사기, 잔고 조회기, 데이터 파일 외에 만들지 않는다.
   - 각 코드 파일은 100줄을 넘기지 않는다. 설명은 파일이 아니라 채팅으로 한다.

5. 끝났을 때
   - 수집기와 검사기를 한 번씩 실행하고 결과를 보여준다.
   - 저장된 봉 수, 첫 봉 시각, 마지막 봉 시각을 보고한다.
   - 실행 명령 세 줄(수집, 검사, 잔고)을 알려준다.

위 조건을 하나라도 지킬 수 없으면 만들지 말고 이유를 먼저 말해라.
```

## 지시문에 일부러 안 쓴 것

봉 시각을 어느 시간대로 저장할지, 아직 끝나지 않은 봉을 어떻게 다룰지는 지시문에 없다. 2화 사규 6절에 이미 있어서다. 사규가 작동하면 지시문 없이도 그대로 나와야 한다. README.md 의 확인 방법 넷째가 이걸 본다.
