# 3화. 봇의 눈 만들기


## 이번 화에서 만드는 것

눈 두 개입니다.

- **시장을 보는 눈.** 업비트에서 시세를 알아서 모아 두고, 빠진 봉이 있으면 스스로 찾아내는 수집기와 검사기
- **내 계좌를 보는 눈.** 업비트 API 키를 발급받아 봇이 내 잔고를 읽게 하는 잔고 조회기

끝나면 봇 폴더에 코드 파일 세 개와 데이터 파일 하나가 생깁니다. 아직 아무것도 사지 않습니다.

## 이 폴더의 파일

| 파일 | 용도 |
|---|---|
| `prompt.md` | 이번 화의 지시문. 클로드코드에 그대로 붙여넣습니다 |
| `api-key-guide.md` | 업비트 API 키 발급 절차. 영상 2부를 글로 옮긴 것 |
| `.env.example` | 키를 넣는 파일의 모양. 이대로 `.env` 를 만들고 값만 채웁니다 |
| `example/` | 제 컴퓨터에서 나온 결과물 예시. 촬영 뒤 추가 |

## 따라 하는 순서

1. `api-key-guide.md` 대로 업비트 API 키를 발급받습니다. 권한은 자산조회, 주문조회, 주문하기. 출금은 주지 않습니다
2. VS Code 로 봇 폴더에 `.env` 파일을 만들고 키 두 줄을 손으로 넣습니다. 채팅창에 붙여넣지 않습니다
3. `prompt.md` 를 열어 대괄호 빈칸 3개를 채웁니다. 아래 "사람이 채우는 빈칸" 참고
4. 2화와 같은 봇 폴더에서 클로드코드를 실행하고 지시문 전체를 붙여넣습니다. 같은 폴더여야 2화 사규가 적용됩니다
5. 몇 분 기다립니다. 중간에 설치할 게 있다고 하면 하라는 대로 합니다
6. 확인 테스트 넷을 합니다. 아래 "확인 방법"

## 사람이 채우는 빈칸

지시문의 1번 항목입니다.

- **종목.** 업비트 마켓 코드로 적습니다. 비트코인은 KRW-BTC, 이더리움은 KRW-ETH
- **봉 간격.** 1시간이 기본입니다. 15분이나 1분으로 바꾸면 더 촘촘하게 모이지만 봉 수가 그만큼 늘어 컴퓨터 용량을 꽤 차지합니다. 1분 봉 1년은 1시간 봉의 60배입니다
- **보관 기간.** 최근 1년이 기본입니다. 5화 백테스트에서 이 데이터를 그대로 씁니다

처음이면 예시 값 그대로 써도 됩니다. 감이 안 오면 클로드코드가 아니라 클로드 앱에 먼저 물어봅니다. 질문 예시입니다.

```
업비트 1시간 봉으로 2종목 1년치를 모으면 봉이 몇 개고 파일 용량은 어느 정도야?
```
```
비트코인, 이더리움 말고 거래량 많은 종목 세 개 더 고르려면 업비트 마켓 코드로 뭐가 있어?
```
```
1분 봉으로 1년치를 모으면 1시간 봉보다 용량이 얼마나 늘어?
```

## 확인 방법

끝났다는 말만 믿지 않습니다. 네 가지를 봅니다. 응답 문구는 매번 조금씩 다릅니다. 숫자와 사실이 맞는지가 기준입니다.

**첫째. 데이터가 들어왔나**
```
저장된 캔들 수와 첫 봉, 마지막 봉 시각을 보여줘
```
봉 수가 계산과 비슷한지, 마지막 봉이 지금 시각 바로 전 봉인지 봅니다. 1시간 봉 2종목 1년이면 봉 수는 1만 7천 개 안팎입니다. 마지막 봉이 몇 시간 전에 멈춰 있으면 수집이 중간에 끊긴 겁니다.

**둘째. 빠진 봉을 알아채나**
```
KRW-BTC 어제 오전 봉 3개를 지우고 검사를 돌려줘
```
결측 3건과 시각이 나와야 합니다. 이어서 수집기를 다시 돌리라고 하면 빠진 세 개만 받아서 결측 0건이 돼야 합니다.

**셋째. 내 계좌를 읽나**
```
잔고 조회를 실행해줘
```
KRW 잔고 숫자가 나오면 키, IP, .env 파일 세 가지가 다 맞은 겁니다. 그리고 VS Code 전체 검색에 Secret Key 앞 네 글자를 넣어 봅니다. `.env` 하나만 나와야 합니다. 코드 파일에서 나오면 즉시 멈추고 키를 삭제한 뒤 다시 발급받습니다.

**넷째. 사규가 일했나**
```
저장된 봉 시각이 어느 시간대인지, 아직 안 끝난 봉은 어떻게 처리했는지 알려줘
```
지시문에는 시간대도 미완성 봉 얘기도 없습니다. 그런데 UTC 로 저장했고 안 끝난 봉은 뺐다고 답하면 2화 사규 6절이 작동한 겁니다. 다른 답이 나오면 아래 "자주 막히는 지점"을 봅니다.

## 자주 막히는 지점

**잔고 조회에서 인증 오류가 난다.** 키보다 IP 를 먼저 의심합니다. 봇이 돌아가는 컴퓨터에서 https://ip.pe.kr 로 지금 IP 를 확인하고, 업비트 발급 페이지에 등록된 값과 다르면 다시 등록합니다. 그다음 `.env` 의 변수명 두 개가 `UPBIT_ACCESS_KEY`, `UPBIT_SECRET_KEY` 그대로인지 봅니다.

**.env 파일을 못 찾는다.** 파일이 봇 폴더 바로 아래에 있는지, 이름이 점으로 시작하는 `.env` 인지 봅니다. `env.txt` 나 `.env.txt` 로 저장되는 경우가 많습니다. 맥 Finder 에서는 점으로 시작하는 파일이 숨겨져 보이지 않습니다. VS Code 탐색기에서는 보입니다.

**파이썬이 없다고 한다.** 클로드코드가 설치 방법을 알려주면 그대로 따라갑니다. 설치가 끝나면 지시문을 다시 붙여넣지 말고 "이어서 해줘"라고 합니다.

**수집이 중간에 멈추거나 요청 제한 오류가 난다.** 업비트는 짧은 시간에 요청이 몰리면 막습니다. 지시문에 간격을 두라는 조항이 있는데 무시됐으면 "요청 사이 간격을 늘리고 제한에 걸리면 기다렸다 재시도하게 고쳐라"라고 시킵니다. 수집기를 다시 실행하면 이미 받은 봉은 건너뛰고 이어받습니다.

**검사에서 결측이 0 이 안 된다.** 다시 받아도 안 채워지는 봉은 업비트에도 없는 봉입니다. 그 시간에 거래가 없었던 겁니다. 지시문 3번대로 "업비트에도 없음"으로 따로 보고되면 정상입니다. 거래량 많은 종목에서는 거의 없고, 작은 종목일수록 많습니다.

**사규 확인에서 UTC 가 아니라고 한다.** 2화 CLAUDE.md 가 이 폴더에 있는지 먼저 봅니다. 다른 폴더에서 실행했으면 사규가 안 읽힙니다. 같은 폴더인데도 다르게 나왔으면 "CLAUDE.md 6절 데이터 규칙대로 고쳐라"라고 시키고 넷째 테스트를 다시 합니다.

**결과 파일 이름이나 구조가 영상과 다르다.** 정상입니다. 같은 지시문이라도 결과는 사람마다 조금씩 다릅니다. 확인 테스트 넷이 통과하면 됩니다.

## 이 수집기의 한계

켤 때마다 빠진 봉을 이어받는 방식입니다. 컴퓨터가 꺼져 있던 동안은 비어 있다가 켜서 돌리면 채워집니다. 24시간 알아서 도는 건 봇 전체가 24시간 돌기 시작하는 7화에서 다룹니다.
